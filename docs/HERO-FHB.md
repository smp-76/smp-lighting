# Hero: реальный FEREKS FHB

Ветка `redesign-preview-v2`. Локальное уточнение выполнено поверх `8dca3c2`: сохранены концепция и layout hero, реальная фотография, управление курсором и промышленная среда. Изменены только hero, его стили, контроллер, соответствующие проверки и материалы просмотра. HTML вне hero, остальные страницы, JSON, исходные изображения, SEO и sitemap сохранены.

## Источники и композиция

Основной ракурс — нижний 3/4: видны оптика, рёбра корпуса и поворотная лира. Переданный reference совпадает с имеющейся фотографией `images/fereks-fhb.webp`, уже с прозрачным фоном. Используется этот исходный файл без ретуши, перерисовки или изменения конструкции. Боковой и верхний reference использованы для проверки формы; переходов через выдуманные промежуточные ракурсы нет. Маленький preview не увеличивается.

Фон — существующее фото `images/reference-logistics.webp`. Это иллюстративная среда демонстрации, не утверждение о поставке FHB на изображённый объект. Слабый общий свет (`opacity: .14`) позволяет различать стеллажи, перекрытия и перспективу. Более яркий слой той же фотографии проявляется под курсором. Широкая мягкая маска с промежуточными ступенями прозрачности сохраняет фактуру поверхностей и плавный falloff. Затемнение слева защищает текст и CTA.

К существующей лире добавлен контекст установки: неподвижная потолочная траверса продолжается за край сцены, стойка и небольшой соединительный узел встречаются с монтажной точкой фотографии. Металл, затенённые кромки и локальные тени отделяют опору от стеллажей. Это схематичное окружение, не монтажный чертёж или новая геометрия самого FHB. Лира и корпус остаются частью исходного фото.

Слева в HTML размещены заданные владельцем H1, подзаголовок и две CTA; они не изменены. Верхняя служебная подпись сокращена до «Подбор под задачу». Справа — предметная сцена и ссылка на существующую `series.html?series=fereks-fhb`. На mobile текст и CTA стоят выше предметной сцены. Фон под подписью продукта больше не образует непрозрачную полосу поперёк луча.

## Движение и свет

- Светильник немного увеличен относительно предыдущего варианта: около 314 px вместо 262 px при viewport 1440; около 189 px вместо 154 px при viewport 390. Положение скорректировано под монтажную опору. Фото остаётся приглушённым (`brightness(.79)`), с читаемыми рёбрами и мягкой тенью; исходный файл сохранён.
- Контролируемый наклон плоскости уменьшен до rotateX ±7°, rotateY ±12°, rotateZ ±2.4°. Боковое перемещение удалено. Центр трансформации совпадает с фиксированной точкой крепления (66.5% / 10.5% фото). Опора и подпись неподвижны.
- Курсор управляет пятном по всему hero, включая область с текстом. Координаты маски и конца луча совпадают с местом наведения.
- Начало луча измеряется по точке на оптике внутри наклонённой фотографии. SVG-конус и градиент пересчитываются между этой точкой и пятном; свет не отрывается от светильника. Проекция немного шире, атмосферная составляющая слабее у источника и плавно затухает по длине. Размытые края и маска фотографии работают совместно; при очень коротком луче дымка ослабляется, не превращаясь в яркое пятно.
- Свет и фото используют одну постоянную времени 220 мс. При уходе курсора сцена мягко возвращается к исходной зоне освещения. Пульсации и автоматического движения нет.
- После затухания движения, вне hero и в скрытой вкладке requestAnimationFrame прекращается. Прокрутка остаётся нативной.
- На mobile, при touch/coarse pointer, reduced motion, экономии трафика и без JavaScript — статичная освещённая зона. При работающем JS неподвижная проекция также один раз привязывается к фактическому положению оптики и уточняется при изменении размера окна. Текст, фотография и CTA остаются доступны.

Световая проекция качественная: реальная КСС, люксы и результаты светотехнического расчёта не имитируются. Плоскость PNG/WebP не вращается на 360°.

`js/light-scene.js` теперь содержит входной контроллер и отдельную функцию отображения состояния фотографии. Впоследствии её можно заменить адаптером настоящей GLTF/GLB-модели. 3D-зависимостей и модели в текущем изменении нет.

## Производительность

Canvas/WebGL в hero нет. Контроллер — около 6.3 КБ исходного JS; изображение FHB — 55 350 байт, с заданными размерами и высоким приоритетом загрузки. Фон — существующий WebP 358 346 байт, повторно используемый в отраслевом блоке. Его загрузка имеет низкий приоритет. Новых изображений или дополнительных запросов для опоры нет: это несколько CSS-элементов. Текст не зависит от декодирования изображения или запуска контроллера. Новых библиотек, шрифтов и сетевых сервисов нет.

Полевые Core Web Vitals не измерены. Локальная проверка Chromium служит для проверки поведения и сдвигов макета, а не для обещания LCP на устройствах посетителей.

## Интерактивная проверка без сервера

JPG показывает только снимок. Для проверки движения подготовлен [автономный HTML](preview-v2/smp-hero-interactive.html).

Проще всего [скачать ZIP](https://raw.githubusercontent.com/smp-76/smp-lighting/redesign-preview-v2/docs/preview-v2/smp-hero-interactive.zip), распаковать его и открыть `smp-hero-interactive.html` двойным щелчком.

Если скачиваете отдельный HTML:

1. Откройте файл по ссылке и нажмите **Download raw file** (значок скачивания справа вверху на GitHub).
2. Откройте скачанный `smp-hero-interactive.html` в Chrome, Edge, Firefox или Safari.
3. На компьютере разверните окно шире 900 px и двигайте мышь по всему hero. Поверхности склада освещаются под курсором, светильник наклоняется вокруг точки установки, луч идёт от оптики к выбранному участку.

На мобильном экране и при reduced motion используется статичная сцена. Картинки, стили и контроллер включены в файл: после скачивания для просмотра не нужны сервер, интернет или установка зависимостей. Здесь показан только hero; ссылки открывают рабочий сайт в новой вкладке.

Файл собирается из текущих `index.html`, CSS и исходного контроллера, без отдельной реализации эффекта:

```sh
python3 scripts/build-hero-preview.py
```

Содержимое автономного файла проверено в Chromium при отключённой сети: изображения доступны, реакция на курсор работает, mobile и reduced motion статичны. На проверенном desktop-экране снимок совпадает с основной страницей пиксель в пиксель.

## Проверки

```sh
python3 tests/data-and-pages.py
node tests/browser.cjs layout home fallback pages-path
node tests/presentation.cjs
```

Проверки включают шесть ширин 375–1920 px, неподвижность без ввода, реакцию фото и света на курсор, совпадение пятна с курсором слева и справа, связь начала луча с оптикой и фиксацию монтажной точки при наклоне. Дополнительно проверяются слабый общий свет, ограничение угла, сохранение источника фото, прекращение обновлений вне экрана, статичная привязка мобильного луча, reduced motion, отключённый JavaScript и отсутствие WebGL. Существующие сценарии отраслей, производителей и инженерного представления также пройдены.

Дополнительно сравниваются контрольные суммы всех файлов вне разрешённого набора и HTML главной за пределами hero. Проверка CSS ограничивает изменения правилами hero. `main` и production не обновляются.

При локальной начальной загрузке Chromium накопленный сдвиг макета равен 0 при 1440 и 390 px. Автономная демонстрация на обеих ширинах совпадает с сайтом пиксель в пиксель и не делает HTTP-запросов. Проверены работа курсора и привязка луча при reduced motion. Контраст на фоне фотографии дополнительно оценён визуально; эти проверки не заменяют полный аудит доступности или полевые Core Web Vitals.
