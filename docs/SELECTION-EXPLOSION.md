# Технический подбор: взрывозащита

Ветка `redesign-preview-v2`. Изменение поверх `e9f2308` ограничено алгоритмом
техподбора и его проверками. JSON, страницы, hero, URL, SEO и sitemap не изменены.

## Причина ошибки

`strictBase()` сначала проверял подкатегорию, затем исключал все модели с
Ex-маркировкой, если отдельный чекбокс `explosion` не отмечен. Выбор подкатегории
«Взрывозащита» не учитывался как требование взрывозащиты. Эти два условия
пересекались: из 134 модификаций в этой подкатегории оставалась только одна.

Это исполнение серии Ex-ДСО с артикулом `2000000131634`: его техническое поле
`explosion_marking` содержит «Нет». Название серии не даёт права считать его
взрывозащищённым. Отдельный чекбокс без подкатегории до исправления уже находил
133 модификации в 11 сериях.

## Проверка всей базы

Проверены все **18 226 моделей / 174 серии** в `catalog-data.json`.
«Маркировка взрывозащиты» хранится в модели как `explosion_marking`.

- **133** модификации содержат реальные Ex-маркировки: 18 различных значений
  с видами защиты и группами IIC / IIIC.
- **18 093** модификации содержат «Нет».
- Пустых значений, отсутствующих полей и `null` в текущей рабочей базе нет.
- Уникальных серий с подтверждёнными маркировками: **11**, все FEREKS.

## Исправление

Подкатегория «Взрывозащита» и чекбокс — два способа задать одно техническое
требование. В обоих случаях принадлежность модели определяется только её
`explosion_marking`: нужен Ex-маркер с видом защиты и группой оборудования.
«Нет», пустые/отсутствующие значения и текстовые заглушки не являются
положительным признаком. Списка разрешённых серий в алгоритме нет.

Для этой специальной подкатегории техническое поле имеет приоритет над
категорийной меткой модели. Назначение, производитель, другие подкатегории и
остальные заданные параметры продолжают ограничивать выдачу. Без требования
взрывозащиты действует прежнее исключение Ex-моделей по умолчанию.

Мощность и поток сохраняют допуск 15% для близких совпадений. Взрывозащита, IP,
КСС, CRI, CCT и монтаж остаются строгими условиями и при близком совпадении.
Перечень требований в результате/письме также учитывает выбор подкатегории.

## Regression-проверки

```sh
node tests/selection-regression.cjs
node tests/selection-explosion.cjs
node tests/browser.cjs selection
python3 tests/data-and-pages.py
```

Пройдены:

- Все 40 прежних сценариев × 18 226 моделей × exact/close. Контрольные
  количества и SHA-256 результатов совпали; `selection-baseline.json` сохранён.
- Полная сверка Ex-выдачи с техническими полями всех моделей; отдельные
  отрицательные проверки «Нет», null, отсутствующего поля и заглушек.
- 173 сочетания параметров для обоих способов выбора Ex с проверкой exact/close;
  все 133 Ex-исполнения проверены с собственным полным набором параметров.
- Привязка к маркировке при изменённых названии/подкатегории тестовой модели,
  сохранение ограничений по назначению и обычным подкатегориям.
- Проверка точной мощности 100 Вт и близких вариантов в пределах 85–115 Вт;
  строгое исключение несовместимых IP, CRI, CCT и производителя.
- Браузер: чекбокс, подкатегория без чекбокса, оба условия вместе, восстановление
  по ссылке, все 11 карточек и все 133 раскрытых исполнения, сброс, сравнение,
  переход в каталог и пустая выдача. Ошибок JS и HTTP нет.
- Неизменность JSON, количества моделей, canonical, SEO, sitemap и локальных
  ресурсов. Дополнительно сравниваются хеши всех файлов вне разрешённой области.
